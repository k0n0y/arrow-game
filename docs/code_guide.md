# 核心代码讲解与答辩准备

这份说明用于理解代码，不能替代本人实际阅读和试玩。

## 1. 数据如何表示

`levels.py` 中的关卡由不可变字符串元组保存。例如第一行 `.DUR` 表示空格、向下、向上、向右。进入关卡时复制成二维列表，之后只修改列表，不改原始关卡。

`DIRECTIONS` 把方向映射成行列变化量：向上 `(-1, 0)`、向下 `(1, 0)`、向左 `(0, -1)`、向右 `(0, 1)`。屏幕 y 坐标向下增加，所以“向上”对应行号减一。

## 2. 为什么不能只看相邻格

对 `R..U`，右箭头的相邻格为空，但更远处的 U 仍然阻挡它。`first_blocker()` 从当前箭头前一格开始，按方向向量扫描到边界，遇到第一个非空格就返回其坐标。

`can_exit()` 还会先确认当前位置确实存在箭头。空格和越界位置均返回 False。循环必须先检查 `0 <= r < rows` 和 `0 <= c < cols`，否则 Python 的负索引可能错误地读取最后一行/列。

单次路径检查最坏时间为 `O(max(R, C))`，额外空间为 `O(1)`；数据格式只在关卡入口校验。

## 3. 为什么贪心求解成立

在本作业的单格基础规则中，箭头只会被删除，不会增加或变换方向。

删除任意一个当前能够离开的箭头，只会减少其他箭头前方的障碍，不会破坏任何已有可行操作。所以求解时可以反复删除任意可消除箭头。如果剩下箭头但没有可执行操作，就是真正的死锁。

该论证依赖本作业规则；如果加入移动后占据新位置等新机制，就不能直接沿用。

实现的求解函数最多经过 A 轮，每轮检查 R×C 个格子，每次射线长度最多 max(R,C)，粗略最坏时间界为 `O(A·R·C·max(R,C))`。实际会按批次删除多支箭；只有小棋盘，不需要复杂优化。

## 4. 状态机如何避免误操作

`MENU`：只能开始或选关。
`PLAYING`：可以点击、提示、重开、返回菜单。
`WON`：当前非最后关已清空，可以下一关。
`LOST`：机会耗尽，棋盘不再接收消除操作，可以重试。
`COMPLETE`：第三关清空，可以从头挑战。

`Game.click()` 只接受 PLAYING 状态。被挡时扣一次生命，畅通时删除一支箭并判断是否完成。界面只负责显示与动画，不重复实现规则。

## 5. 动画为什么不会影响规则

规则先立即确定成功或碰撞，再用 `MoveResult` 保存方向和原位置，界面据此绘制 0.48 秒动画。
动画期间锁住棋盘点击，但仍可重开或回菜单。重开会清除动画、提示和计时。这样不会出现动画结束后再删除新棋盘上同一个位置的问题。

## 6. 鼠标坐标如何转换

先判断点击位于棋盘矩形内部，再计算：

```python
col = (mouse_x - board_left) // cell_size
row = (mouse_y - board_top) // cell_size
```

还要判断是否位于格子的实际可点区域（格子之间留有间隙）。界面外、间隙、空格都不扣失误数。

## 8. 本人试玩步骤

第一关先故意点击第 1 行第 2 列的向下箭头（下方存在障碍），观察扣一次机会且箭头保留；随后点第 1 行第 3 列向上箭头，观察飞出。点击“重新开始”，确认全部箭头和三次机会恢复。

再尝试连续三次点被挡箭头，观察失败后重试。最后独立通过三关；不会时可用 H 提示。记录真实结果、是否使用提示及发现的问题。
